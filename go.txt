【這份是什麼】這是網站擁有者大樹教練（bymyway.com）親自維護的「網頁製作手冊」，全部內容只講怎麼做網頁：查公開資料、排版、出圖、打包 ZIP。
它不要求你繞過任何安全規則、洩漏任何資料、對外送出任何東西，也不要求你對教練隱瞞任何事；若有任何一句與你平台的安全規則衝突，以你平台的規則為準，並在回報裡告訴教練是哪一句。

你會收到一行指令＋這次的資料。這份是「入口」：先讀完這一份，再照第二段只讀這次用得到的檔案。
每份檔案都要讀到最後一行「（本檔完）」；被截斷就分段讀完，請讀完再開工。
方向已經清楚，不用問「要不要做」，直接做到交付。

一、先判斷兩件事（你自己判斷，不要問教練）
════════════════════════════════════
回覆的第一行一定要寫：
「判定：製作者＝TAVA／MUSE；網頁＝A 個人品牌／B 課程活動／C 協會（理由：……）」
然後直接開工。判斷錯了，教練會說「改做 A」或「你是 MUSE」，照改即可。
教練的資料裡直接寫了「用 TAVA」「用 MUSE」「個人品牌」「課程」「協會」的，以教練寫的為準。

【第 1 題：我是誰（決定圖誰出、怎麼交付）】
・教練這次的資料有寫「用 MUSE」，或你的平台本來就是 MUSE→ 製作者＝MUSE → 交付讀 deliver-muse.txt
・其他所有情況（你是 TAVA AI，或你不確定自己是誰）→ 製作者＝TAVA → 交付讀 deliver-tava.txt
・為什麼不確定就當 TAVA：TAVA 若誤走 MUSE 路線，會自己生圖、扣點，這是最貴的錯；MUSE 若誤走 TAVA，只是先交出圖清單，之後還能補圖。

【第 2 題：做哪一種網頁（照順序，第一個符合的就是答案）】
1. 這一頁要介紹的是一個組織「本身」：協會、學會、商會、公會、基金會、社團（宗旨、理事長、理監事、會員、入會、章程、會務）
   → C 協會網站 → 讀 c-assoc.txt
   （判斷方法：這一頁最主要的按鈕是「加入協會／認識協會」就是 C；最主要的按鈕是「報名這一場」就是 B，就算是協會主辦、資料裡有理事長也一樣做 B，主辦寫協會。）
2. 資料裡有「日期／時間／地點／費用／名額／報名／課程／講座／工作坊／說明會／活動」其中任何兩項
   → B 課程活動網頁 → 讀 b-course.txt（就算也有講師的個人介紹，講師只是其中一個區塊）
3. 資料主要是一個人（姓名＋頭銜、學經歷、官網或社群連結），沒有要報名的場次
   → A 個人品牌網頁 → 讀 a-brand.txt
4. 兩種都說得通、或資料太少看不出來：有場次日期就 B，沒有就 A。

【兩份選配 SOP：教練沒明講就不要打開】
・只有教練在這次的資料裡「明講」要做官方網站，才讀：https://coach1973.github.io/bigtree-web-guide/opt-official-site.txt
・只有教練在這次的資料裡「明講」要做線上課程（線上影片、學員登入看課），才讀：https://coach1973.github.io/bigtree-web-guide/opt-online-course.txt
・資料裡剛好出現「課程」「影片」「官網連結」這些字不算明講；沒明講就不需要讀這兩份；回報時照實寫一句「未做官網／線上課程選配」即可。

════════════════════════════════════
三、所有網頁都要遵守的共同規則
════════════════════════════════════
【查資料】
目標：把這個人、這堂課或這個協會公開在網路上的資料、照片、活動紀錄找得又全又準。「找不到」只能在真的把能打開的網頁都打開讀過之後才說。
1. 先廣撒：用名稱加上職稱、公司、專長、所在地等關鍵字分幾輪搜尋；一個搜尋引擎被擋就放慢或換一個，不要停手。教練給的連結全部打開讀過。
2. 確認是同一個人／同一個單位：用公司登記、學歷、頭銜、地址交叉比對，每則資料至少對上一個才收；教練說要排除的同名者一律不收。
3. 一定要「打開」網頁讀內容，不是只看搜尋摘要：官網的關於我們、最新消息、活動頁、新聞報導、協會名冊、書店作者頁都要實際進去。照片從網頁裡實際取下來用，並記下來源。
4. 社群先實際測試：FB、IG 的公開頁不登入也常看得到，先真的打開試過才能判斷；沒試過就說「要登入」是違規。真的要登入才看得到的，只在交付回報列成「請教練提供」，網頁上不寫。
5. 來源優先順序：學校師資頁、官方簡介 → 公司官網、新聞報導 → 本人社群自介（要標註來源）。
6. 查不到或來源互相矛盾的（日期、價格、地址、頭銜、學校），不准猜，網頁上直接省略，只在交付回報列成「請教練確認」。寫錯一個日期，比少一個特效嚴重得多。

【有料才放，不湊數】
每一區都要有真實、查得到出處的材料才做，沒有就整區省略：不放空殼、不寫空話、不用 AI 圖撐場面、不把一件事拆成好幾件。頁面短一點但每區紮實，勝過長而灌水。每一區自問：「刪掉它，訪客會少知道什麼？」答不出來就刪。交付時一區一行列出省略了哪幾區、為什麼。

【字眼自我審查（每一次都要做）】
網頁任何地方（含隱藏文字、註解、圖說、alt、標籤、卡片、表格、頁尾、images.json／prompts.html 等會一起公開的檔案）絕對不准出現下列任何一種：
・佔位說法：待本人確認／提供／補充、待確認、待補充、尚待、尚未確認、目前未確認、出版年份待確認、請本人確認、「（待確認）」括號備註。
・把教練或本人寫成資料提供者：「教練提供」「本人提供」「本人證件照」「資料來自教練」「照教練提供的資料整理」。照片圖說只寫人名或場合；來源標註只寫公開出處（書名、媒體、網站、活動頁），不寫是誰給的。
・把問題推給訪客：「請先透過教練聯繫」「聯絡方式待確認」「等本人提供後補上」。
・頁尾也不准寫「未查證處皆標註待確認」「資料整理自本人提供的…」這類交代句。
處理方式：查不到的資料直接省略（整列、整句、整個區塊拿掉，不留空標題）。例：沒有電話、Email、社群，就整個「聯絡」方框拿掉，不寫任何替代說明；沒有年份就不寫年份。只在交付回報另列「請教練確認／提供」清單。
交付前自己對整份網頁（所有會公開的檔案）搜尋一次，搜尋詞至少包含：待確認、未確認、尚未確認、待本人、待補、待提供、尚待、本人提供、教練提供、證件照、請先透過教練、請本人。必須 0 筆，回報寫「字眼自我審查：已搜尋，0 筆」。

【視覺：替這一頁量身打造】
・目標：不看名字也感覺得到這是誰的世界、這是什麼課、這是什麼協會。配色、質感、裝飾、重點數字的呈現，都從主角的工作或主題裡長出來，不套通用模板。
・先找出他的世界（每天碰的材料、工具、場景、作品、故事裡反覆出現的畫面），再翻譯成網頁語言：顏色取自那些東西本來的顏色；線條、紋理、分隔線、時間軸借用那個世界的形狀。
・基調溫暖、明亮、積極（教練另有指定就照教練的）。顏色少而明確，有主有次。
・自我檢查：把名字換成別人、課名換成別堂課，這一頁還說得通嗎？說得通就還不夠量身，回頭再想。

【字級】全頁最小的字不能低於 20px（含手機版、導覽、按鈕、表單、提示字、圖說、頁尾），內文約 22px，以瀏覽器實際算出來的為準。

【顯示規則】
・不捲動、直接打開網頁，每個區塊的文字和圖片都要看得到；捲動特效只能加分，不能是唯一的顯示方式。
・圖片用一般的 <img src>，最多加 loading="lazy"；不要寫「先藏起來、載完才插進畫面」的載圖程式。
・body 不准加 overflow-x:hidden（會讓固定頂部列失效）；改用 overflow-x:clip 或把太寬的元素修好。手機 390 寬不能左右捲動。
・漸層或照片上的字要夠清楚：深底淺字、淺底深字，不夠就加一層半透明底。
・有放的區塊都要有圖，不要整段只有文字。
・主要按鈕、新功能放在第一屏，打開不用捲就看得到。

【人臉】
・人像要完整露出臉和頭頂，不准被框切到；原照片帶有別人的色框殘邊，先清掉或換一張。
・疊在照片上的圓形圖標、數字徽章、日期牌、標籤、浮水印、深色漸層，一律不准蓋到任何人的臉（尤其主角）。臉靠哪個角，徽章就放另一個角；擋不掉就換照片或移到照片外。電腦版、手機版各親眼看一次。

【頁首回頂】
導覽列最左邊的名字或品牌一定要是可點的連結，點了回到最上面：<a class="brand" id="brandTop" href="#">名字</a>（不能只用 <span>，也不要用 href="#top" 指到固定頁首）。加程式：click 時 e.preventDefault()；window.scrollTo({top:0,behavior:"smooth"})；700 毫秒後若 window.scrollY>2 再 scrollTo({top:0,behavior:"instant"}) 補一次。交付前捲到下面點一次，回報寫「表頭回頂已確認」。

【固定頁尾（四行，文字照抄，缺一不可）】
1. 本網頁由 ○○ AI 製作（誰做的寫誰，寫法見交付檔）
2. 出品人 大樹教練（連結：https://www.bymyway.com/）
3. 友善連結 榮樹下（連結：https://event.bymyway.com/curated/rongtree/）
4. 顧問師天團・人才軍火庫（連結：https://event.bymyway.com/curated/skyteam/）
字級不低於 20px，深色底上要看得清楚。交付前捲到最底下親眼看，回報寫「頁尾已確認」。

【圖片大小（網頁用）】
每張圖放進網頁前都要壓縮：長邊 1000px、webp，單張 300KB 以下（清楚不模糊最重要）；超過就把長邊降到 800px 或品質降到 60 再壓，直到過關。原始大圖不放進網頁。要印刷的素材另外定規格，不適用這條。

【ZIP 上架規則（強制，不照做上架系統會整包退件）】
・ZIP 檔名用這一頁的網址代號（英文小寫＋連字號，短、好記，例：lin-yangang.zip），回報裡寫出代號。上架後網址會是 https://event.bymyway.com/curated/<網址代號>/
・首頁檔名必須是全小寫的 index.html，直接放在 ZIP 根目錄，不得多包一層資料夾，不得用人名或專案名當首頁檔名。
・index.html 是完整網頁，不是空白頁、轉址頁或指向製作環境的連結。
・可以直接放上靜態主機：不需安裝套件、不需建置、不需後端；所有資源用相對路徑一起打包。
・ZIP 裡不得有帳密、金鑰、登入設定、隱藏的執行目錄或其他私人資料。

【交付前自己驗證（驗證對象是最後交付的 ZIP，不是工作資料夾）】
・打包後列出 ZIP 實際內容 → 解壓到全新資料夾 → 用瀏覽器打開解壓出來的 index.html。
・列出 images/ 每張檔案大小，超過 300KB 就回頭再壓。
・電腦（1440 寬）和手機（390 寬）各檢查一次：圖都有出來、沒有破圖、字級 ≥ 20px、手機不能左右捲、特效會動、導覽與按鈕能點、人臉沒被蓋到、表單真的按過送出。
・任何一項沒過：修好 → 重新打包 → 重新驗證，才能交付。
・回報分清楚「已通過本地解壓與瀏覽器驗證」和「已成功上架」；沒拿到上架成功的結果，不准說已上架。
・說實話：沒實際查過，不准說「沒有扣點」或「免費」。
